菜单功能模块 Agent 拆分方案

原则：地基先行 → 业务域垂直切片 → 并行开发 → 集成联调

阶段0 · 公共地基（一个 Agent 串行完成，其他 Agent 等它）
① 数据库全部表结构dept / user / role / menu / role_menu / category / knowledge_base + 五级权限字段
② 初始化数据内置超级管理员 + 6个菜单 + 默认角色
③ 登录 + JWT认证、Redis会话
④ RBAC 权限中间件接口级鉴权，全局复用
⑤ 前端脚手架路由守卫 + 登录页 + 布局框架
▼ 地基完成后，三路 Agent 并行 ▼
Agent A · 组织域
负责模块：部门管理 + 用户管理
DB · 部门树表 + 用户表（含 dept_id）
API · 部门树CRUD + 用户分页CRUD
FE · 部门树页面 + 用户列表页
校验 · 删除关联校验 / 用户必选部门
Agent B · 权限域
负责模块：角色管理 + 角色授权
DB · 角色表 + role_menu 关联表
API · 角色分页CRUD + 菜单树授权
FE · 角色列表页 + 授权勾选树页
校验 · 菜单动态渲染 + 接口拦截
Agent C · 知识域
负责模块：知识库分类 + 知识库上传
DB · 分类树表 + 文档表（五级权限字段）
API · 分类树CRUD + 文档分页/上传/删除
FE · 分类树页面 + 文档列表上传页
校验 · 五级权限落库 + 无修改操作
▼ 三路交付后，统一集成 ▼
阶段2 · 集成联调
统一数据初始化 / 菜单动态渲染全链路验证 / 权限绕过测试（越权访问被拦截）
阶段3 · 验收
按 PRD V1.1 逐条核对：树形无限级 / 分页 / 五级权限 / 角色授权即时生效
建议：先让 Agent A（组织域）跑通最小闭环（部门→用户），作为模板验证表结构、分页、前端页面套路无误后，再放行 Agent B / C 并行，避免 3 个 Agent 按错误套路返工。
