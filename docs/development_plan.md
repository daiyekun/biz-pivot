## 一、开发总体目标

根据《商枢 BizPivot 企业智能AI平台产品需求文档 V1.1》与《数据库详细设计文档 V1.1》，本项目采用**阶段性迭代开发模式**。

整体目标：搭建一套**企业级、权限可控、数据隔离、私有化AI智能平台**，包含：

- 全局登录鉴权（Token + Redis 会话）
- 系统内置**唯一、不可删除、不可禁用**的超级管理员账号
- 系统菜单初始化 + 后台 RBAC 权限体系（部门/用户/角色/角色授权）
- **无限级树形结构**：部门管理、知识库分类
- **表格列表统一分页规范**
- 企业私有 RAG 知识库问答 + **文档五级数据权限体系**（个人/部门/公司/部门及子部门/跨部门）
- **文档上传强权限管控**：仅授权角色可上传，不支持修改仅支持新增/删除
- **可控跨部门知识检索与隔离**
- AI 闲聊对话（多轮、上下文智能压缩、SSE 流式）
- 智能数据可视化报表 + 报表文件导出
- 分布式无状态、可水平扩展部署

**核心开发原则：先底座、后权限、再业务、强隔离、最后部署上线**

## 三、开发核心规范（强制）

1. **严格分层**：API路由层 → Service业务层 → Repository仓储层 → 存储（PG/Redis/Qdrant/MinIO），单向依赖，禁止乱层调用。
2. **所有权限校验必须后端完成**：前端仅做展示隐藏（UI 层），接口层二次拦截，防绕过。
3. **所有耗时任务一律 Celery 异步**：文档解析、切片、向量化、报表计算、部门权限展开重建。
4. **所有会话 / 上下文全部外置 Redis**：服务无状态，支持分布式多实例部署。
5. **知识库文档权限统一收敛到 `knowledge_permission` 明细表**：拒绝在 knowledge_base 冗余权限字段。
6. **表格类列表强制分页**：`pageNum` / `pageSize`（默认10，最大100），返回 `records/total/pages`。
7. **树形页面不分页**：部门、知识库分类一次性加载整树（节点数据量大时预留懒加载）。
8. **数据状态位统一**：`state`：0=启用/显示，1=禁用/不显示，3=删除（软删除）。
9. **功能迭代必须同步更新文档**（PRD / 开发计划 / 接口文档）。

## 五、分阶段详细开发计划

### 阶段一：项目架构与基础底座搭建（地基阶段）

**阶段目标**：搭建前后端完整工程结构、统一规范、完成底层能力封装，为所有业务模块提供支撑。

**开发内容**：

- 后端 FastAPI 全局架构：应用入口 `main.py`（注册路由、全局异常、CORS、生命周期）、`config/settings.py`（环境变量统一加载）、`config/constants.py`（上下文阈值、最大 Token、分页参数、权限枚举）
- `core/` 底层能力封装：
  - `redis_client.py`：Redis 全局连接 + 缓存工具
  - `llm_client.py`：统一 LLM 客户端（兼容 OpenAI / Ollama / 国产模型，支持流式）
  - `sse_generator.py`：SSE 流式消息封装（状态推送 + 文本流推送）
  - `exceptions.py`：全局异常定义与统一捕获
  - `token_service.py`：Token 统计、上下文占用率、自动压缩/摘要
  - `auth.py`、`permission.py`：认证与权限核心（阶段二细化）
- 数据库模型初始化：按数据库设计文档创建全部表结构（12 张表）与迁移/初始化脚本（超管、菜单种子数据）
- 前端 Vite + Vue3 基础架构：路由、Pinia stores、Axios 封装、SSE 封装、公共组件（聊天框、文档上传、报表图表、Markdown 渲染、树组件、分页表格）
- Celery 初始化：`tasks/celery_app.py`（broker/result 配置）、worker 启动入口 `celery_worker.py`

**阶段交付物**：

- 可运行的前后端骨架 + 全部依赖服务（PG/Redis/Qdrant/RabbitMQ/Jaeger）连通
- 数据库初始化脚本与 12 张表的模型落地
- 底层 AI 能力、Redis、SSE、异常、配置统一可用

### 阶段二：登录鉴权体系 + 内置超级管理员

**阶段目标**：实现全局登录鉴权，未登录禁止任何功能；系统内置唯一超级管理员，支持禁用账号彻底失效。

**开发内容**：

- 系统初始化**内置超级管理员账号**（固定、唯一、不可删除、不可禁用），启动时自动创建
- 登录接口（`POST /api/v1/auth/login`）：超级管理员与员工统一入口，密码加密存储（pwd + slot 加盐）
- 禁用账号禁止登录，返回「账号已被禁用」友好提示
- Token 生成 / 刷新 / 登出：JWT，会话写入 Redis（分布式无状态）
- 全局鉴权拦截中间件：未登录访问所有接口一律拒绝并跳转登录
- `api/deps.py`：全局依赖注入（当前用户、Token 校验）
- 登录页前端（`views/login/index.vue`）

**阶段交付物**：

- 登录/登出/Token 刷新完整闭环
- 内置超级管理员可登录
- 禁用账号无法登录，越权访问全部拦截

### 阶段三：系统菜单初始化 + 后台管理（部门/用户/角色）

**阶段目标**：完成企业组织权限体系：菜单初始化、无限级树部门、用户、角色管理、账号禁用启停。

**开发内容**：

1. **系统菜单初始化**（启动自动写入 `sys_menu`，state=0）：
   - 部门管理（无限级树形，不分页）
   - 用户管理（列表分页）
   - 角色管理（列表分页）
   - 角色授权（角色选择分页 + 授权区）
   - 知识库分类（无限级树形，不分页）
   - 知识库上传（列表分页）

2. **部门管理**（`api/v1/dept.py`、`services/dept_service.py`、`repositories/dept_repo.py`）：
   - 无限级树形结构（pid + `path` 物化路径字段，如 `/1/3/5/`），整树一次加载，预留懒加载
   - 新增/修改/删除：修改支持更换父级（防循环嵌套校验）；删除前校验存在下级部门或归属用户则禁止删除
   - `is_company` 区分公司节点（根节点）与部门节点，冗余 `company_id`

3. **用户管理**（`api/v1/user.py`、`services/user_service.py`、`repositories/user_repo.py`）：
   - 列表分页展示 + 分页组件（pageNum/pageSize，默认10，最大100）
   - 新增用户**必须选择归属部门**（必填）；支持绑定角色（多选，写 `sys_user_role`）
   - 编辑 / 删除（删除前校验关联数据）/ 密码重置 / **启用禁用账号**
   - 支持按用户名、部门筛选，筛选后分页重置第一页

4. **角色管理**（`api/v1/role.py`、`services/role_service.py`、`repositories/role_repo.py`）：
   - 角色列表分页展示
   - 新增/修改/删除；删除前校验是否存在用户绑定，存在则禁止删除
   - 角色名称、描述、启用/禁用状态

**阶段交付物**：

- 系统 6 个后台菜单初始化完成
- 部门无限级树 CRUD、用户分页管理、角色分页管理
- 账号启用/禁用、密码重置、部门归属、角色绑定全部可用

### 阶段六：RAG 知识库 + 五级数据权限体系（核心）

**阶段目标**：实现企业级安全的知识库：仅授权角色上传、异步解析、文档**五级数据权限**精准隔离、可控跨部门检索。

**开发内容**：

1. **知识库分类管理**（`api/v1/category.py` + `views/admin/category/index.vue`）：
   - 无限级树形分类（pid + path），整树加载不分页
   - 新增/修改/删除；删除前校验下级分类或已关联文档存在则禁止删除
   - 分类名称、父级、排序

2. **知识库上传 / 管理**（`api/v1/rag.py`、`views/admin/knowledge/index.vue`）：
   - **强上传管控**：默认所有普通角色无上传权限；仅角色授权配置【文档上传/管理/分类管理】权限的角色可用；无权限者前端隐藏入口、后端直接拦截
   - 上传必填：知识库名称、描述、归属分类、**文档数据权限（五选一）**
   - 文档上传：支持 PDF / MD / TXT；MD5 唯一去重；文件存本地/MinIO；**不支持修改，仅支持新增/删除**
   - 删除文档同步删除其全部权限明细与向量数据
   - 文档列表分页展示（超级管理员看全部，其他角色按五级权限过滤）

3. **文档五级数据权限落地**（对齐数据库设计 V1.1 `knowledge_permission` 明细表）：
   - 上传时按权限类型**展开写入明细表**：
     - 1 个人：1 行（target_id = 上传者 user_id）
     - 2 部门：1 行（target_id = 所选部门 id）
     - 3 公司：1 行（target_id = 公司 id）
     - 4 部门及子部门：N 行（目标部门 + 全部子孙部门，用 path 展开）
     - 5 跨部门：N 行（每个被选部门一行）
   - 部门结构变更（新增/移动/删除）→ Celery 异步任务重建受影响文档的「部门及子部门」展开行
   - 删除文档 → 同步删除该 kb_id 全部权限行

4. **RAG 检索权限过滤核心链路**（对齐数据库设计 V1.1 3.3 节）：
   - 用户登录/检索时计算「主体集合」缓存 Redis：`my_user_id`、`my_company_id`、`my_dept_ids`（由 path 解析出部门链）
   - 检索主路径：
     1. Redis 白名单命中 `user:docs:{uid}` → 直接取可访问 doc_id 集合
     2. 未命中 → `knowledge_permission` 单表简单 IN 查询兜底回填（`SELECT DISTINCT kb_id WHERE target_id IN (...)`）
     3. Qdrant 检索：`filter = doc_id IN (白名单) AND category_id = ?`
     4. 仅用有权片段组装 Prompt → LLM 生成
   - 无权限文档彻底屏蔽：不召回、不参与 Prompt、不展示、不泄露
   - 权限变更（上传/删除/授权调整）主动失效相关 Redis 缓存，保证实时生效

5. **异步解析任务**（`tasks/rag_tasks.py` + `doc_parse_task` 表）：
   - Celery 异步：文件解析 → 切片 → 向量化入库（Qdrant）
   - chunk payload 冗余 `doc_id`、`category_id`
   - 任务状态落表（待执行/执行中/成功/失败）+ 失败重试 + 耗时任务进度可视化

**阶段交付物**：

- 知识库分类树、文档上传/删除/分页管理
- 五级数据权限完整落地（明细表展开 + 主体集合 + 检索过滤）
- 上传权限强管控（UI 隐藏 + 后端拦截双保险）
- 文档「不支持修改」规则生效
- RAG 问答接入对话页开关，可控跨部门检索完成

### 阶段七：智能可视化报表 + 报表导出

## 六、接口与分页通用规范

### 6.1 REST 接口规划（api/v1）

| 模块       | 前缀                  | 主要接口                                                                                     |
| ---------- | --------------------- | -------------------------------------------------------------------------------------------- |
| 鉴权       | `/api/v1/auth`        | login / refresh / logout / profile                                                           |
| 部门       | `/api/v1/dept`        | 树查询 / 新增 / 修改 / 删除（防循环嵌套、防误删）                                            |
| 用户       | `/api/v1/user`        | 分页列表 / 新增 / 修改 / 删除 / 启用禁用 / 重置密码                                          |
| 角色       | `/api/v1/role`        | 分页列表 / 新增 / 修改 / 删除（校验用户绑定）                                                |
| 菜单授权   | `/api/v1/menu`        | 菜单树 / 角色可访问菜单 / 保存角色菜单授权 / 知识库权限配置                                  |
| 知识库分类 | `/api/v1/category`    | 树查询 / 新增 / 修改 / 删除（校验下级与文档关联）                                            |
| 知识库 RAG | `/api/v1/rag`         | 上传（含五级权限）/ 分页列表 / 删除 / 解析任务进度 / 检索                                     |
| 对话       | `/api/v1/chat`        | 会话 CRUD / 消息 SSE 流式（含 RAG 开关）                                                     |
| 报表       | `/api/v1/report`      | 数据查询 / 图表生成 / AI 解读 / 导出 / 异步任务进度                                          |
| 系统       | `/api/v1/system`      | 健康检查 / 系统配置 / 模型配置                                                               |

### 6.2 分页入参约定（V1.1 强制）

- `pageNum`：页码，默认第 1 页
- `pageSize`：每页条数，默认 10；下拉选项 10 / 20 / 50 / 100
- 后端强制限制最大 `pageSize = 100`，禁止一次性拉取全表

### 6.3 返回数据结构

```json
{
  "records": [],
  "total": 0,
  "pages": 0
}
```

### 6.4 前端交互规则

- 底部展示分页组件（上一页/页码/下一页/跳页）
- 搜索/筛选条件变更 → 重置第 1 页
- 删除成功保持当前页码刷新；新增成功回到第 1 页

### 6.5 后端规则

- 所有表格接口必须分页，禁止全表查询
- 分页查询自动带入当前登录用户身份，同步完成功能权限、数据权限过滤
- 分页统一 LIMIT（keyset），禁止深分页 OFFSET

| 表名                   | 用途               | 关键点                                             |

## 八、关键技术难点与解决方案

| 技术难点                        | 解决方案                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------- |
| RAG 知识库五级数据权限精准隔离  | 权限统一收敛 `knowledge_permission` 明细表；检索走「Redis 白名单 + 单表 IN 兜底 + Qdrant payload 过滤」双保险，无权限数据到不了 LLM |
| 部门及子部门权限              | 写入时用 path 展开成 N 行明细，避免检索递归；部门结构变更触发 Celery 异步重建展开行           |
| 跨部门可控知识共享              | 五级权限中的「部门及子部门 / 跨部门」响应多选部门，展开明细控制可见范围                        |
| 大文档解析阻塞接口              | 全部 Celery 异步解析/切片/向量化，`doc_parse_task` 状态落表 + 前端进度轮询                   |
| 文档上传权限管控                | 默认全员无上传权限，仅授权角色可上传；前端隐藏 + 后端接口二次拦截双保险                    |
| SSE 多实例部署会话丢失          | 对话上下文 / 会话全部外置 Redis，服务无状态，支持分布式负载均衡                              |
| LLM 上下文超长卡顿              | 内置 Token 统计 + 自动摘要压缩机制，智能控制上下文长度                                       |
| 防止权限绕过、数据越权          | 所有权限后端统一校验（`core/permission.py`），前端仅做展示隐藏                               |
| 部门/分类无限级树性能           | path 物化路径免递归；整树一次加载，节点量大预留懒加载                                        |

## 十二、开发核心规范总结

- 严格按照分层架构开发，单向依赖，禁止乱层调用
- 所有权限校验**必须后端校验**

- 所有功能迭代必须同步更新文档
