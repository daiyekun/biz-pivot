# 架构说明（写进 README）

## ✅ 单体架构（当前开发 V1）

**适用阶段：现阶段开发、快速落地、团队小**
优点：

1. 开发简单，代码统一，调试方便
2. 部署简单，一套后端代码，Docker Compose 一键拉起所有依赖
3. 模块之间直接函数调用，没有服务间网络开销
缺点：
4. 所有模块共享同一个进程，任何模块 CPU 高会影响整体
5. 扩容只能整体水平扩容，不能单独扩容知识库 / AI 对话模块

## ✅ 微服务架构（未来 V2）

**适用阶段：用户量大、多租户、不同模块负载差异大**

- 按领域拆分成独立服务，可以独立发布、独立扩容
- 使用 RabbitMQ 作为消息总线，异步任务解耦
- 数据库分库，不同业务数据隔离
- 网关统一入口，统一鉴权、限流
缺点：运维复杂度显著提升，分布式事务、服务发现、链路追踪等问题需要额外处理
